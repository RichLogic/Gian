# Kimi Code

## 1. 在 Gian 中做什么

Kimi Code Integration 通过 Kimi 的 ACP 接口把编码会话接入 Gian。Gian 展示消息、计划、工具活动和交互，Kimi Runtime 负责模型任务与原生会话。它不是控制 Kimi 网页，也不通过解析终端屏幕来获取回答。

模型与思考选项由当前 Runtime 返回；同一 Proxy 能处理多个发行版本，不表示每个上游版本都能直接替换到受管安装中。

## 2. 支持的能力与限制

- 支持文本、本地文件、图片、会话重命名、原生会话发现与历史重放。
- 支持问题/权限交互、思考、计划和用量事件；不要把计划事件、工具活动与独立 Diff 事件混为一种能力。
- 旁路对话和分叉取决于当前 ACP Runtime 是否实际支持 session/fork。界面应在条件不成立时禁用并说明原因，不能只凭 Proxy 名称假设可用。
- 协议 2.3 提供只读自定义项清单；条目可能是部分可见或上游不支持，不能把空清单解释成用户没有配置。
- 当前适配器不宣告 turn.steer、按 Turn 分叉或原生历史删除。MCP 相关支持也应按具体已协商能力判断，不能从“CLI 有 MCP”推导所有 Gian Host 服务都可用。

权限和工作区限制继续生效。文件输入能力不等于可以访问授权范围之外的路径。

## 3. 运行原理与进程关系

```text
Gian Host
  -> 可复用的 Kimi Proxy
      -> kimi acp 子进程
          -> 原生 Session 与模型服务
```

Proxy 的进程范围是 shared。在对应启动绑定内复用 ACP 连接，通过结构化请求与通知映射 Gian Session 和 Kimi 原生 Session。共享程序/连接不代表不同 Agent 可以混用 HOME。

ACP 的 terminal 工具由受控终端服务处理。取消、关闭会话或 Runtime 退出时，需要清理相应进程组并等待清理屏障；遇到无法确认清理成功的情况会失败并保留诊断，不应假装终端已经退出。

Agent 的登录维护终端属于 Workbench 的维护用途，不等于 ACP 执行工具的终端，也不是新的 Session TTY 运行模式。

## 4. 安装与依赖

从 Agent Integrations 中安装 Kimi Code。Gian 读取签名 Catalog 中具体选定的 Kimi Runtime 归档、Proxy 及摘要，验证安装计划、解压结果与真实版本后再激活。

```text
<dataDir>/runtimes/kimi/<runtime-version>/<artifact-sha256>/kimi
```

不要用系统 PATH 中另一份 Kimi 代替该目录中的受管版本。历史的 Kimi CLI 发行版本与后来的 Kimi Code 发行版本需要按实际制品辨认；Manifest 的兼容版本列表、Catalog 选定版本和这台机器的当前版本是三个不同概念。

安装不复用用户的登录凭据，也不要求先建立一个装有账号数据的 Agent HOME。程序安装完成后再为需要的 Agent 配置 HOME。

## 5. 第一次使用

1. 安装 Integration，等待 Runtime 组合激活，先排除下载、摘要、解压和版本检查错误。
2. 添加 Kimi Agent，为独立配置选择新的托管 HOME。
3. 打开该 Agent 的 CLI 维护终端，按 Kimi 当前版本的官方流程登录或配置服务。不要在普通任务消息里发送登录密钥。
4. 返回详情检查状态，再在授权工作区创建会话。
5. 先尝试小任务，检查计划、工具权限和完成状态。需要分叉或旁路时，确认 Runtime 真的返回该能力。

如果已有会话恢复失败，应保留原生 Session/HOME，按错误处理；不能自动清空历史后把一个新 Session 标成恢复成功。

## 6. HOME 与隔离

Kimi 通过 KIMI_CODE_HOME 使用所选 Agent 状态目录。Gian 托管 HOME 为：

```text
<dataDir>/homes/kimi/<agentId>/
```

它包含该 CLI 的配置、认证、会话、缓存和日志等状态。多个 Agent 默认使用不同 HOME；若选择同一已有 HOME，就会共享这些状态，不能宣称它们拥有独立账号和历史。

HOME 不是程序安装目录，也不是项目沙箱。不要把 Runtime 归档解压到 HOME，或通过移动 HOME 改写已有会话的程序绑定。Gian 不自动导入或清空自定义 HOME；CLI 对自己的状态目录仍可能进行正常升级写入。

## 7. 反向代理与自定义端点

在选定 HOME 中按当前 Kimi Runtime 的官方配置方式选择 Provider、模型和端点。不要把 Claude 或 Codex 的配置文件原样搬过来，也不要以修改 Gian Web/Host 地址代替模型服务配置。

先在同一 Agent 的维护终端检查官方 CLI 是否可用，再看 Gian 的 ACP 映射。一个端点能返回普通文本，不代表其工具调用、图片、思考和用量行为完整兼容。

不同端点或账号使用不同 Agent HOME 管理。不要为了临时切换全机环境变量而影响其他 Agent，也不要把 HOME 中的认证、原生历史或完整配置上传到 Issue。

## 8. 操作注意事项

- 受管更新使用 Catalog 选定的完整组合，不从 CLI 的自动更新通道擅自换程序。
- Kimi 历史状态格式可能变化。CLI 能启动并不证明旧会话能恢复；恢复失败要显式报告并保留数据。
- 若关闭或中断报告终端清理失败，先确认相应进程确实结束。不要直接去掉屏障或删除锁来继续执行。
- 用量显示来自 Runtime 的结构化通知或其已支持的查询方式，不通过随意匹配一条终端文案补造消耗。
- 更新时先结束同类 Turn 和维护终端。隐藏维护区块不会自动停止它。

## 9. 故障排查

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 页面显示的目标版本与记忆中的 CLI 版本不同 | Catalog 选定制品和 Manifest 兼容列表 | 以当前认证组合为目标，不手填任意旧/新版本 |
| 没有模型或认证失败 | 这个 Agent 的 KIMI_CODE_HOME | 在对应维护终端完成配置，不借用另一 HOME 的状态 |
| 分叉/旁路按钮不可用 | Runtime 是否支持 session/fork 及会话状态 | 使用当前可用动作，不伪造分叉 |
| 原生会话恢复超时或失效 | 原生 Session 是否存在、错误是否可重试 | 保留历史并按恢复提示处理，不清空 HOME |
| 中断/关闭提示终端清理失败 | 是否仍有活动工具进程及明确错误码 | 结束实际占用后重试；不要把失败当成功 |
| 文件/图片输入被拒绝 | 当前能力和路径授权 | 使用受支持输入，避免越权路径 |
| 用量长期不变化 | Runtime 版本、当前事件与查询结果 | 提交脱敏的版本和阶段信息，不仅截取一行文本 |

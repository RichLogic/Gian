# Claude Code

## 1. 在 Gian 中做什么

Claude Code Integration 把 Claude Code 的编码会话接入 Gian。你在 Gian 中选择工作区、发送任务、查看工具活动并处理权限请求；真正访问项目和执行模型任务的是厂商 CLI，Gian 负责会话、文件授权、状态展示和受管程序的生命周期。

它不是一个直接调用任意模型 HTTP 接口的聊天框，也不是给 Claude 网页套壳。Gian Proxy 是协议适配器；把模型请求转发到自定义地址的 LLM 反向代理是另一层配置。

## 2. 支持的能力与限制

- 支持文本、本地文件和图片输入；输入仍受 Host 的路径、大小和授权检查约束，不代表所有文件类型都有专用解析器。
- 支持会话重命名、原生会话发现和历史重放，以及问题/权限交互。
- 支持旁路对话、会话分叉和按可用 Turn 边界分叉；是否可以立即操作，还要看当前会话是否有可用边界、活动 Turn 或待处理交互。
- 支持思考与用量事件，以及协议 2.3 下的只读自定义项清单。界面模型、思考和模式选项来自当前 Proxy/CLI，不在本说明中固定一张模型表。
- 不宣告原生历史删除和 turn.steer。没有宣告的操作不能靠按钮或文本指令假装完成。

工具执行仍受 Claude Code 的权限与模式约束。隐藏在 UI 后面的自动化任务也不能绕开这些权限。Gian 不保证某个第三方端点实现了 Claude Code 所需的所有协议行为。

## 3. 运行原理与进程关系

普通会话的主要关系是：

```text
Gian Host
  -> 当前 Gian Session 的 Claude Proxy
      -> 当前 Turn 的 claude -p 子进程
          -> 配置的模型服务
```

Claude Proxy 的进程范围是 session。它通过结构化请求/事件与 Host 通信，不抓取交互式终端画面作为会话协议。每个 Turn 启动结构化 CLI 子进程，后续 Turn 使用已保存的厂商原生 Session 身份恢复上下文。旁路对话/分叉使用独立的原生会话边界，不是把内容插进原会话后再撤销。

CLI 终端是另一种用途：让你完成厂商登录和维护配置。它属于 Workbench 的维护终端，不是恢复已经移除的 Session TTY 模式。模型服务的计费以厂商当前规则为准，不承诺沿用网页或交互式终端的订阅额度。

## 4. 安装与依赖

在 Agent Integrations 中选择 Claude Code，执行“安装”。Gian 使用签名 Catalog 指定的 Proxy 与 Claude CLI 组合，下载后校验摘要，按 Proxy 提供的安装计划放到受管目录，检查实际程序版本，再原子激活。

程序位置由当前 dataDir 决定，典型布局是：

```text
<dataDir>/runtimes/claude/<runtime-version>/<artifact-sha256>/bin/claude
```

不要先在系统 PATH 安装另一份 CLI，再把它当成 Gian 的受管安装；也不要修改受管目录中的二进制或链接。Gian App/Host 提供运行 Proxy 所需的 Node 环境。具体目标版本由当前 Catalog 组合决定，不能把厂商“最新版本”直接替换进来。

纯 Web 调试环境与完整桌面环境的下载、凭据代理能力可能不同。页面可以展示目录，不等于该环境已经具备完整安装条件；若安装报代理不可用，应按诊断处理，不能绕过来源或摘要校验。

## 5. 第一次使用

1. 先安装 Claude Code Integration，等待完整 Runtime 组合激活成功。只有 Proxy 文件可见不代表 CLI 已安装。
2. 点击“添加 Agent”，选择已安装的 Integration。为新配置使用新建的 Gian 托管 HOME；仅在明确要复用现有厂商配置时选择已有 HOME。
3. 在 Agent 详情打开 CLI 维护终端，按 Claude Code 自己的流程完成登录或模型服务配置。不要把凭据粘贴到普通会话、Catalog 文档或 Issue。
4. 完成后退出维护命令，返回 Agent 详情确认状态。程序安装成功与账号/端点配置完成是两个独立检查点。
5. 为授权的项目创建会话。第一次使用先发送一个范围小的任务，确认工作区、模型和权限提示都符合预期。

安装失败时先看失败阶段，保留原有 Agent、HOME 和历史。重试安装不应该重建账号或清空会话。

## 6. HOME 与隔离

Claude Code 的配置根通过 CLAUDE_CONFIG_DIR 指向所选 Agent HOME。托管 HOME 通常位于：

```text
<dataDir>/homes/claude/<agentId>/
```

其中保存 CLI 自身的配置、认证与原生历史等状态。两个 Agent 可以共享同一受管 CLI/Proxy 程序版本，但使用不同 HOME。若主动选择同一个已有 HOME，它们就会共享该 HOME 的厂商配置和历史，不能再称为账号隔离。

Gian 不自动复制、清空或迁移你的自定义 HOME；CLI 会按自身正常行为读写所选目录。HOME 隔离不是文件系统沙箱，项目读写权限仍由工作区授权和 CLI 模式控制。已有会话保留其创建时的 HOME，不应靠修改目录位置迁移会话。

## 7. 反向代理与自定义端点

需要反向代理时，在该 Agent 的 HOME/CLI 配置中使用当前 Claude Code 支持的端点与认证设置。不要改 Gian 的 Host 地址、Catalog URL 或 Proxy 安装路径来切换模型服务。

使用类似 claude-mix 的既有配置时，复用的是其配置 HOME，而不是把包装脚本作为第二条“底层 CLI 路径”。受管程序仍由 Gian 安装；先确认原包装脚本是否还有 HOME 之外的行为，不能只凭脚本名称声称配置完全等价。

配置后先在同一个 Agent 的维护终端确认 CLI 能使用该服务，再回 Gian 建会话。兼容 Anthropic 消息格式不等于完整兼容 Claude Code 的流式事件、工具、思考或上下文语义；不兼容时应缩小配置范围或改回已验证服务。

## 8. 操作注意事项

- 更新作用于同类 Proxy 的全局程序组合，不只影响当前选中的 Agent；先结束该类正在运行的 Turn 和维护终端。
- 隐藏终端不等于停止进程。更新等待时应查看真正持有 Runtime 的操作，不要直接删除锁文件。
- 不单独更新 CLI、Proxy 或修改认证文件。旧程序保留用于恢复/诊断，不代表任意旧版本都能读取已经前向迁移的厂商数据。
- 删除 Agent 不等于删除厂商原生历史。处理故障时不要以清空 HOME 作为默认修复。
- 报告问题时保留错误码、发生阶段、Proxy/CLI 版本与经脱敏的日志，不上传完整 HOME。

## 9. 故障排查

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| Integration 列表为空 | Catalog 状态和网络错误 | 刷新目录；签名、序列或摘要错误不要用不受信来源绕过 |
| Proxy 有版本但 Runtime 显示未安装 | 当前激活组合是否存在 | 在 Integration 详情安装 Runtime，不编辑 CLI Path |
| 安装完成但 Agent 仍要求配置 | 该 Agent 的 HOME 是否已完成厂商配置 | 打开这个 Agent 的 CLI 终端处理，不用另一个账号的 HOME 掩盖错误 |
| 登录有效但模型请求失败 | 端点、模型和权限提示 | 在同一 HOME 排查厂商服务；先去掉未经验证的代理扩展 |
| 工具或文件输入被拒绝 | 输入能力、工作区授权、CLI 权限模式 | 使用当前宣告的输入方式，按正常权限交互授权 |
| 分叉/旁路动作不可用 | 是否有边界、活动 Turn 或待处理交互 | 等待状态允许；不要手工修改原生 Session ID |
| 更新一直等待 | 同类 Turn、维护终端是否仍运行 | 正常停止占用者后重试，不强删锁或程序目录 |
